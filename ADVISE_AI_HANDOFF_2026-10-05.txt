============================================================
1. PROJENİN AMACI
============================================================

AdVise AI; Instagram/Meta reklam yönetimi, içerik üretimi, otomasyon, müşteri/abonelik/lisans yönetimi ve AI destekli karar sistemini tek uygulamada toplamak için geliştiriliyor.

AI tarafındaki ana hedef:
- Kullanıcı mümkün olduğunca az alan doldursun.
- Kullanıcı fotoğraf/video seçsin.
- AdVise AI görseli/medyayı analiz etsin.
- Ürünü, markayı, modeli ve görünen metni çıkarsın.
- Gerçekten görülen teklif/fiyat varsa tespit etsin.
- İçerik açısını kendi seçsin.
- Tonu kendi seçsin.
- Hook, caption, CTA, hashtag üretsin.
- POST/REELS/CAROUSEL önerisi versin.
- Paylaşım zamanı önerisi versin.
- Hedef kitle ve reklam önerisi üretsin.
- Zaman içinde hangi hook/ton/açı/saatin işe yaradığını öğrenen kalıcı bir AdVise AI hafızası olsun.

Önemli ürün kararı:
Gemini tamamen kaldırılmayacak. Gemini ilk aşamada güçlü AI üretim motoru/öğretmen olacak. AdVise AI'ın asıl uzun vadeli farklılaştırıcı tarafı ise ayrı bir kalıcı 'Hafıza Sarayı' katmanında tutulacak.

Hafıza Sarayı model ağırlıklarını eğitmez. Geçmiş üretim ve performans verisini saklar ve sonraki Gemini çağrısına bağlamsal öğrenme olarak geri verir. İleride istenirse küçük/yerel bir model veya başka sağlayıcı ile bu hafıza kullanılabilir.

2. BUGÜNE KADAR YAPILANLAR
============================================================

A) Görsel yükleme sorunu çözüldü.
İlk sürümlerde JPG/PNG seçimi HTTP 400 dönüyordu.
Eski Multer MIME filtresi çok katıydı.
Dosya uzantısına göre de medya tespiti yapan IMAGE_EXTENSIONS ve VIDEO_EXTENSIONS eklendi.
JPEG/PNG/WebP/GIF/BMP/HEIC/HEIF/AVIF/TIFF ve MP4/MOV/M4V/WEBM/AVI/MKV/3GP/MPEG/MPG/OGV kabul edilecek şekilde genişletildi.

B) Eski içerik-pack route içindeki hatalı image MIME kontrolü bulundu ve kaldırıldı.
Bu kontrol, upload kabul edilse bile AI analizini 400 ile durduruyordu.

C) Telefon tarafından Android/Dart bazen
mimetype = application/octet-stream
gönderilse bile uzantıdan JPG olduğu tespit edilip
visionMime = image/jpeg
olarak işleniyor.

Örnek başarılı upload logu:
[AI MEDIA]
originalName: scaled_1000114270.jpg
mimetype: application/octet-stream
kind: IMAGE
size: 473504
visionMime: image/jpeg
hasImageDataUrl: true

D) Cloudflare/public route doğru backend'e gidiyor.
GET /health üzerinden lokal 3001 ile public hostname aynı build marker'ı döndürdü.

E) OpenAI denemesi yapıldı.
OPENAI_API_KEY olmadığı için LOCAL_FALLBACK kullanıldı.
Daha sonra OpenAI API yerine Gemini kullanma kararı alındı.

F) Gemini API anahtarı .env'den başarıyla okunuyor.
Kontrol komutu:
node -e "import('dotenv/config').then(()=>console.log('GEMINI_API_KEY mevcut:',!!process.env.GEMINI_API_KEY,'uzunluk:',(process.env.GEMINI_API_KEY||'').length,'MODEL:',process.env.GEMINI_MODEL||'gemini-3.8-flash'))"

Başarılı sonuç:
GEMINI_API_KEY mevcut: true
MODEL: gemini-3.8-flash

API key asla sohbet/GitHub'a gönderilmemeli.

G) Gemini REST yaklaşımı ilk denemede çalıştı ancak:
- responseSchema içinde JSON Schema'dan gelen additionalProperties alanı Gemini tarafında kabul edilmedi.
Bu alanlar kaldırıldı.

H) Sonraki aşamada Gemini'nin resmi JavaScript SDK'sına geçildi:
@google/genai
ve Interactions API kullanılmaya başlandı.

backend/package.json içine:
"@google/genai": "^2.27.0"
eklendi.

Kullanılan temel yaklaşım:
GoogleGenAI({apiKey})
client.interactions.create(...)

Gemini sayfasında görülen güncel örneklere dayanarak:
- Interactions API
- multimodal input
- structured output / response_format
yaklaşımı kullanılıyor.

I) Görsel ve video için multimodal yapı kuruldu.
20 MB'a kadar medya inline olarak gönderiliyor.
Daha büyük medya için Gemini Files API kullanılacak şekilde kod hazırlandı.
Video, Reels olarak sınıflandırılıyor.

J) Gemini 3.8 Flash geçici 503/high demand hatası verdi.
Log:
[AI GEMINI RESPONSE] { status: 503, ok: false }
This model is currently experiencing high demand.

Bunun üzerine retry + model fallback eklendi:
3 deneme, exponential backoff
sonra GEMINI_FALLBACK_MODEL
varsayılan fallback: gemini-3.7-flash

.env.example:
GEMINI_API_KEY=
GEMINI_MODEL=gemini-3.8-flash
GEMINI_FALLBACK_MODEL=gemini-3.7-flash

K) Gemini Interactions isteğinde 60 saniyelik timeout eklendi.
Böylece request sonsuza kadar asılı kalmıyor.

L) Sağlık kontrolü:
GET /health şu anda:
{
  "ok": true,
  "app": "AdVise AI",
  "version": "14.0.0",
  "buildMarker": "GEMINI_INTERACTIONS_2026_10_03_V1",
  "uploadMode": "EXTENSION_AWARE",
  "aiImageMode": "GEMINI_INTERACTIONS_MULTIMODAL"
}

Bu daha önce lokal 3001 ve public Cloudflare endpointinde test edildi.

4. HAFIZA SARAYI SİSTEMİ
============================================================

Yeni dosya:
backend/src/ai-memory.js

Yeni başlangıç verisi:
backend/data/ai_memory.json

Hafıza tenant bazlı çalışıyor.

Her tenant için:
generations
patterns:
  hooks
  angles
  tones
  formats
  times
  audiences
outcomes

saklanıyor.

A) learnFromGeneration(tenantId, pack, input)
AI tarafından üretilen içeriği hafızaya kaydeder.

Kaydedilen başlıca bilgiler:
- productName
- brand
- model
- hook
- caption
- cta
- hashtags
- selectedTone
- contentAngle
- recommendedFormat
- recommendedPostTime
- contentGoal
- targetAudience
- visualSummary
- creativeScore
- source
- modelUsed
- postId
- üretim zamanı

B) learnFromOutcome(tenantId, input)
Reklam performansı ile daha önceki üretimi ilişkilendirir.

Şu sinyaller kullanılıyor:
- spend
- messages
- ctr
- messageCost
- adId
- postId

Bunlardan bir outcomeScore hesaplanıp ilgili hook/açı/ton/format/saat/hedef kitle skoruna işleniyor.

C) buildMemoryContext(tenantId)
Hafızadan en güçlü öğrenilmiş örüntüleri seçer ve Gemini promptuna ekler.

Gemini'ye:
GÜÇLÜ HOOKLAR
GÜÇLÜ İÇERİK AÇILARI
GÜÇLÜ TONLAR
GÜÇLÜ FORMATLAR
GÜÇLÜ SAATLER
GÜÇLÜ HEDEF KİTLELER
SON ÜRETİMLER

olarak bağlam veriliyor.

Bu sayede her yeni içerik:
'Gemini ilk defa gördü'
gibi değil,
'AdVise AI'ın daha önce öğrendiği şeyler var; bunları yeni medya bağlamında kullan'
şeklinde ele alınacak.

Önemli:
Bu sistem gerçek ML model eğitimi değildir.
Kalıcı dış hafıza + retrieval + prompt bağlamıdır.
Gelecekte bunun üzerine gerçek model fine-tuning/yerel model katmanı eklenebilir.

D) GET /api/ai/memory
tenant bazında hafıza özetini döndürmek için eklendi.
Şimdilik UI zorunlu değil; debug ve yönetim için kullanılabilir.

5. HAFIZANIN GERÇEKTEN ÖĞRENMESİ NASIL ÇALIŞIYOR?
============================================================

İçerik üretildiğinde:
Gemini -> sonuç -> learnFromGeneration()

Post oluşturma akışlarında postId ile ilişkilendirilmesi hedefleniyor.
Böylece daha sonra Meta'dan 12 saatlik performans geldiğinde aynı post bulunabilecek.

Optimizer içinde:
EARLY_REVIEW_DONE
işleminden sonra launch.postId varsa
learnFromOutcome()
çağrılıyor.

Yani:
İçerik
-> hook
-> ton
-> açı
-> format
-> saat
-> hedef kitle
-> yayın
-> reklam
-> 12 saat performans
-> messageCost/CTR/messages
-> outcomeScore
-> hafıza puanı
-> sonraki Gemini çağrısı

şeklinde öğrenme döngüsü kurulmuş durumda.

============================================================
6. UYGULAMADAKİ REKLAM MOTORU
============================================================

Mevcut optimizer.js zaten 12 saatlik karar motoruna sahip.

Ana yaklaşım:
- Meta reklamlarını çek.
- Reklamın launch zamanını bul.
- 12 saat dolmadan sert karar verme.
- 12 saat sonunda spend/messages/CTR/messageCost çıkar.
- Kural motoruna gönder.
- Gerekirse reklamı durdur.
- Serbest bütçeyi daha iyi reklam setine aktar.
- EARLY_REVIEW_DONE logu yaz.
- Aynı performans verisini AI hafızasına aktar.

Bu taraf Gemini'ye bağlı değil.
AI hafızası sadece kararların yanında öğrenme sinyali olarak kullanılıyor.
